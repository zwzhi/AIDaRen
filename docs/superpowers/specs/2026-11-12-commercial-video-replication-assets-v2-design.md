# 商业视频复刻资产与自动化编排 V2 设计规格

## 1. 目标

把近期确定的商品持久研究、商品多状态、共享服饰库、达人参考图自动匹配、授权声音样本和自动化编排正式纳入复刻系统。商品和达人资产只在首次建立或增量更新时研究，后续作品直接复用已确认版本。

## 2. 核心决策

- 商品创建默认入口是“商品图 + 商品名称 + 自然语言描述”。网页研究是后台异步补全，不阻塞草稿保存。
- 商品研究结果持久化到商品资产内部；刷新只产生候选增量，不能覆盖已确认字段。
- 商品是商品家族、具体变体、不可变版本和状态集合的组合。SKU、色号、规格可以为空；没有明确变体时使用 `single_variant` 或 `user_defined`，存在歧义时阻止生成。
- 商品状态首期覆盖：包装态、打开/取用态、使用/细节态、质地/试色态、效果态。镜头按需引用状态，不要求创建时一次性补齐全部状态。
- 服饰独立于达人。服饰素材可按个人、团队或项目共享；真正进入生成的是 `actor_version + wardrobe_version` 的达人专属穿搭效果。
- 达人参考图保存角度、表情、景别、姿态、服饰版本和来源时间。每个镜头只检索 Top 1～3 张相关参考图。
- 声音样本绑定达人并保存质量、授权和供应商版本。原始样本只用于声音身份参考；新台词使用生成后的统一主声音轨。
- 15 秒是 H3 单段上限，不是固定时长。分段支持 4～15 秒可变时长、重叠、转场和最终裁剪。
- 预览阶段允许片段并行；正式阶段按连续性依赖混合并行，并通过边界质量检查和局部重做修复接缝。
- 所有联网研究、外部素材、动作能力和卖点都保留来源、抓取时间、内容 hash、置信度和人工状态。

## 3. 资产对象

### 3.1 商品

- `CvProduct`：商品家族。
- `CvProductVariant`：SKU、色号、容量、套装等变体，可为空身份字段。
- `CvProductVersion`：变体的不可变事实、卖点、禁用表达和素材快照。
- `CvProductResearchRun`：一次联网/多模态研究任务，保存输入 hash、模型版本、状态和刷新原因。
- `CvProductSource`：网页、说明书、旗舰店、用户上传资料的快照，保存 URL、域名、抓取时间、内容 hash、来源等级和权利状态。
- `CvProductFactCandidate`：字段级候选值、证据引用、置信度、冲突状态和人工确认记录。
- `CvProductState`：包装态、打开态、取用态、使用态、质地态等状态。
- `CvProductStateAsset`：状态对应的图片/视频资产和来源角色。
- `CvProductCapability`：商品动作能力、前置条件、适用镜头、禁止条件、证据资产和审核状态。

### 3.2 服饰

- `CvWardrobeItem`：服饰单品。
- `CvWardrobeVersion`：颜色、材质、款式、素材和权利快照。
- `CvWardrobeSet`：多件单品组成的完整穿搭。
- `CvActorWardrobeLook`：指定达人版本穿指定服饰版本的标准效果图和审核状态。
- 服饰范围支持 `personal`、`team`、`project`，读取和生成权限继承共享范围。

### 3.3 达人参考图

- `CvActorReferenceSet`：达人版本的参考集合。
- `CvActorReferenceFrame`：单张参考图，保存 yaw/pitch、表情、景别、姿态、服饰版本、来源时间、质量状态和检索 embedding/hash。
- `CvAnchorFrame` 增加最终采用的达人参考帧 ID、商品状态 ID、服饰版本 ID 和引用选择记录。

### 3.4 声音

- `CvVoiceSource`：从授权视频或音频提取的原始声音样本，保存切片范围、音频 hash、噪声/音乐/单人评分和授权证据。
- `CvVoiceProfile` 增加样本版本、provider voice handle、能力探针状态、语言、授权范围和质量状态。
- `CvVoiceRender` 继续保存脚本 hash、声音版本、统一主轨和实际时长。

## 4. 商品研究和增量合并

1. 用户上传商品图，填写名称和可选描述，系统立即保存草稿。
2. 后台异步抓取官方站点、官方旗舰店和说明书，使用 Gemini 输出结构化候选。
3. 系统按商品图片、名称、规格和来源字段解析变体；冲突时进入 `ambiguous`。
4. 候选字段和状态资产进入待确认区，已确认字段不可被自动覆盖。
5. 新研究只追加新状态、新来源或新候选；冲突字段生成新版本候选并记录原因。
6. 用户确认后发布新的 `CvProductVersion`，历史作品继续引用旧版本。
7. 后续项目读取已发布版本；只有缺少状态、用户主动刷新或来源超过 TTL 时才执行增量研究。

网页抓取必须在隔离环境中执行，限制域名和重定向，网页正文只作为不可信数据传给模型，不能执行页面中的指令。网页图片默认是研究参考，不直接成为最终生成资产。

## 5. 镜头匹配和生成

- Gemini 为每个镜头输出 `product_presence`、`product_state`、`product_action`、`required_asset_roles`、服饰需求和置信度。
- 参考检索器根据源帧的角度、表情、景别、姿态和服饰需求选择达人参考图 Top 1～3。
- 商品匹配器只选择当前商品版本已确认的状态和能力；缺失状态进入人工补充或转场替代路径。
- Image2.6 使用源锚帧、达人参考、商品状态参考和服饰效果图生成候选锚帧；Flare 用于候选，Sunburst 用于确认后的最终锚帧。
- H3 只消费冻结后的锚帧、脚本、声音条件和分段参数，不直接消费未经审核的商品或服饰素材集合。

## 6. 自动化编排

新增 `CvWorkflowRun`、`CvWorkflowStageRun` 和人工门记录，阶段支持：

`research`、`analyze`、`script`、`anchor_candidate`、`voice`、`anchor_finalize`、`segment_plan`、`render`、`continuity_qa`、`compose`、`final_qa`。

商品研究、视频分析、素材质检可以并行；Flare 候选和声音生成可以并行；H3 独立片段可以并行。低置信度、权利缺失、商品身份歧义、卖点冲突和锚帧质量失败必须暂停到人工门。

每个阶段需要幂等键、依赖关系、重试策略、取消状态、最近成功节点和失败原因。

## 7. 长视频连续性

每个 segment 保存：

- `source_duration_ms`
- `request_duration_ms`
- `adopted_duration_ms`
- `overlap_ms`
- `transition_type`
- `transition_duration_ms`
- `trim_start_ms`
- `trim_end_ms`
- `continuity_anchor_time_ms`
- `repair_status`

片段首尾自动检查人物、服饰、商品状态、光线、动作方向、黑帧、花帧和音画漂移。轻微差异使用短转场、运动模糊、遮挡或叠化；严重差异只重做异常片段或交界处。

主声音轨是唯一权威声音。H3 原生声音只有在真实能力探针通过且试听确认后才能作为可选路径。

## 8. 权限、成本和审计

- 商品、服饰、达人、声音和外部来源都继承个人/团队/项目权限。
- 每个真实模型调用前检查对应角色的 capability gate，不允许只验证 H3 就开启全链路付费。
- 报价必须包含研究、图片、声音、视频分段、重做和人工审核成本。
- 最终 manifest 必须保存脚本、商品版本、商品状态、服饰版本、达人参考图、声音样本、主声音轨、转场、分段输出、来源和审核链。
- 输出下载后校验 MIME、时长、音轨、hash 和文件完整性。

## 9. 验收门

- 同一商品第二次使用不重新执行完整研究，只读取已发布状态集。
- 新镜头缺少一个状态时只补该状态，不重建整个商品。
- 已确认字段不会被刷新覆盖，冲突可回滚。
- 同一服饰可在多个达人上复用，但每个达人有独立的穿搭效果版本。
- 同一源帧不会把所有达人参考图全量传给 Image2.6。
- 60 秒和 120 秒视频可以按 4～15 秒可变片段批量生成并局部修复。
- 真实 API 未通过角色级能力探针和最小请求验证前，保持 Mock/沙箱模式。
